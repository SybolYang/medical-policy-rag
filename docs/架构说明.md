# 项目架构说明

> 这份文档回答三个问题：每个文件夹是什么、数据怎么在里面流、七步链路对应哪些代码。
> 面试展示 / 以后回看项目时直接用。

## 一、顶层目录

```
medical-policy-rag/
├── data/          数据（原料 + 半成品）
│   ├── raw/         原始语料：55 篇政策 .md —— 唯一真数据，进 git
│   └── processed/   加工产物：向量索引/切片/缓存 —— 可重建，不进 git
├── src/           源代码：七步链路每个模块
├── eval/          评估：评测集 + 打分脚本（第7步）
├── docs/          文档：决策记录 + 本架构说明
├── .venv/         Python 虚拟环境（第三方包），不进 git
├── .git/          版本历史
├── README.md      项目说明书
├── requirements.txt  依赖清单（复现环境用）
├── .env.example   环境变量模板（API key 填这，真 .env 不进 git）
└── .gitignore     声明哪些不上传
```

一句话记法：
- `data/` = 料（生的 raw + 熟的 processed）
- `src/` = 机器（加工料的流水线）
- `eval/` = 质检台
- `docs/` = 说明书 / 工作日志
- 带 `.` 的（`.venv`/`.git`/`.env`）= 环境工具，不是业务代码

## 二、data/raw vs data/processed（最易混）

| | data/raw/ | data/processed/ |
|---|---|---|
| 装什么 | 55 篇政策原文 .md | index.faiss（向量）、chunks.json（切片文字+来源）、cache.json（问答缓存） |
| 谁生成 | 抓取脚本 `../抓取医保语料.py` | `python -m src.main build` |
| 进 git | 进（宝贵原始数据） | 不进（删了能一键重建） |
| 前端类比 | 源图 .psd | 打包出的 dist/ |

`.gitignore` 里 `data/processed/*` + `!data/processed/.gitkeep` = 忽略产物，但保留一个空 `.gitkeep` 让空目录能被 git 追踪（git 不追踪空文件夹）。

## 三、src/ 九个文件对应流水线哪一站

```
config.py       总配置（路径/模型名/切分参数）——所有模块都读它
   │
   ├─ 离线建库 4 步 ───────────────────────────
loader.py       ① 加载：读 data/raw/*.md → Document[]
chunker.py      ② 切分：Document → Chunk[]（技巧①：按句子+重叠）
embedder.py     ③ 向量化：Chunk 文字 → 512 维向量（bge-small-zh）
vectorstore.py  ④ 入库：向量存进 Faiss → data/processed/index.faiss
   │
   ├─ 在线问答 ────────────────────────────────
vectorstore.py  ⑤ 检索：问题→向量→搜 top-k（同一文件兼检索）
rerank.py       ⑤.5 重排（可选，--rerank 才启用）
generator.py    ⑥ 生成：拼「引用约束 prompt」→ 调大模型（技巧②）
cache.py        ⑦ 缓存：同问题秒回，存 data/processed/cache.json（技巧③）
   │
main.py         总指挥：串成 build / ask / demo 三个命令
```

注：`vectorstore.py` 一个文件干两步（④入库 + ⑤检索），因为存和查操作同一个 Faiss 索引。
`__init__.py`（src、eval 各一个）是空文件，把目录标记成 Python 包，才能 `python -m src.main` 运行、模块间才能 `from . import config`。

## 四、两条流程

### 流程 A：离线建库（跑一次，`python -m src.main build`）
```
data/raw/55篇.md
   │ ①loader 读进来
   ▼ 55 个 Document{标题,正文,来源}
   │ ②chunker 按句子切 + 重叠 60 字
   ▼ 560 个 Chunk{段文字,来源}
   │ ③embedder 转成向量
   ▼ 560×512 数字矩阵
   │ ④vectorstore 存进 Faiss
   ▼ data/processed/index.faiss（向量）+ chunks.json（文字+来源）
```

### 流程 B：在线问答（每次提问，`python -m src.main ask "问题"`）
```
"生育津贴怎么发放?"
   │ 先查 cache.json → 命中直接返回（技巧③，省钱）
   │ 没命中 ↓
   │ ⑤embedder 把问题转成向量
   │ ⑤vectorstore 拿问题向量去 index.faiss 搜最像的 top-4
   ▼ 4 个最相关 Chunk（带出处）──（可选 rerank 再排序）
   │ ⑥generator 把「问题 + 4 段原文」拼成带引用约束的 prompt
   │ ⑥丢给大模型 → 生成带 [来源N] 的答案
   ▼ 答案 + 出处 → 存进 cache.json 备下次
```

### 第 7 步评估（另一条线，`python -m eval.evaluate`）
```
eval/dataset.json（6 题：问题+标准答案+标准出处）
   │ 对每题跑「流程 B 的检索部分」
   ▼ 比对检索到的文件 vs 标准出处
   ▼ 算出 命中率 / Top1命中 / 召回率（按类别分组打印）
```
未覆盖题（标准出处为空）单独拎出、不计检索分——它考的是生成层会不会老实拒答，需人工/LLM 判。

## 五、当前真实数字（可复算）
- 建库：55 篇 → 560 切片，向量矩阵 (560, 512)，CPU 向量化约 1 分钟，索引 1.1 MB。
- 检索质量（6 题种子，5 题计分）：hit@4 = 100% / Top1 = 100% / 平均召回 = 100%。
- ⚠️ 种子题偏简单、命中率虚高；扩到 30 题、加跨文档/口语化/未覆盖后才有说服力，简历只写那时的真实数字。

## 六、常用命令
```bash
# 离线建库（首次会下载 bge 模型，走 hf-mirror 镜像）
python -m src.main build
# 在线问答（没配 API key 时是 dry-run，只打印引用约束 prompt）
python -m src.main ask "浙江省生育津贴从2025年7月1日起怎么发放？"
python -m src.main ask "..." --rerank   # 启用重排
python -m src.main demo                 # 内置示例
# 评估
python -m eval.evaluate --top-k 4
```
